# Security Policy

## Reporting a vulnerability

Please report security vulnerabilities privately through [GitHub private vulnerability reporting](https://github.com/Dev-Dyl-NZ/bracket-control-wiki/security/advisories/new). Do not disclose security-sensitive details in a public issue or pull request.

Relevant reports include exposed credentials or private data in published documentation, unsafe executable content, cross-site scripting, or a documentation change that could cause users to weaken the security of Bracket Control.

For vulnerabilities in the Bracket Control application itself, use the private reporting instructions in the [Bracket-App security policy](https://github.com/Dev-Dyl-NZ/Bracket-App/security/policy). Ordinary documentation errors without security impact can use the repository issue tracker.

Use only systems and accounts you own or are explicitly authorized to test. Do not disrupt services, perform high-volume scanning, access other users' data, or test the production application without written authorization. Stop and report immediately if you encounter secrets or personal data.

We aim to acknowledge reports within five business days and will coordinate remediation and disclosure based on severity. This is not a bug-bounty programme and does not promise compensation or legal safe harbor.
